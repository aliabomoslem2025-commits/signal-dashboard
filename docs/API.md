# Signal LAN Dashboard

## API compatibility

The dashboard consumes the local-auth sidecar API. It does not call the Java Signal Server directly.

| Operation | HTTP | Path |
|---|---|---|
| Health check | GET | `/healthz` |
| List users | GET | `/v1/local-auth/admin/users` |
| Create user | POST | `/v1/local-auth/admin/users` |
| Delete user | DELETE | `/v1/local-auth/admin/users/{phone}` |
| Enable/disable user | PATCH | `/v1/local-auth/admin/user-status/{phone}` |
| List devices | GET | `/v1/local-auth/admin/users/{phone}/devices` |
| Enroll device | POST | `/v1/local-auth/admin/users/{phone}/devices` |
| Revoke device | DELETE | `/v1/local-auth/admin/devices/{deviceId}` |
| Audit events | GET | `/v1/local-auth/admin/events?limit=100` |

All administrative calls use `Authorization: Bearer <LOCAL_AUTH_ADMIN_TOKEN>`.

## Device enrollment

The Android client must export the Android ID and a public ECDSA P-256 SubjectPublicKeyInfo PEM generated by Android Keystore. Paste those values into the device enrollment form. Only the public key is sent to this dashboard. Never export or upload the private key.

## Run in development

```sh
npm install
npm run dev
```

Vite serves the UI on port 5173. Set the API base URL in the sign-in page to the HTTPS auth service origin. Configure that exact UI origin in the sidecar's `ALLOWED_ORIGINS`.

## Container deployment

The container serves the dashboard on port 8088 and proxies `/v1/local-auth/*` and `/healthz` to the sidecar service name `local-auth:8090`.

The Compose file expects to join the sidecar's Docker network. Set `LOCAL_AUTH_DOCKER_NETWORK` to the actual network name created by the local-auth Compose project if it differs from `local-auth_private`.

By default, the published dashboard port binds to loopback. Put a trusted HTTPS reverse proxy in front of it, or deliberately set `DASHBOARD_BIND_IP=0.0.0.0` only when a trusted LAN TLS proxy or firewall controls access.

## Security notes

- The administrator token is held in browser session storage only and is cleared on explicit sign-out or tab-session teardown.
- Use HTTPS in production. The UI refuses non-loopback HTTP.
- Do not expose the local-auth sidecar or dashboard directly to the public Internet.
- Restrict browser origin via the sidecar's exact `ALLOWED_ORIGINS` setting.
- Audit events are bounded to the newest 100 records.
